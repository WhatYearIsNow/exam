# 题库数据与项目交接

## 职责边界

`exam` 维护网页题库及答题功能，保留经过确认的题目修正，并在需要时提供题库数据。

完整 PDF 题册、附图处理、多选题排版、来源解析、统一目录和连续页码由 `zhenti-pipeline-v2` 负责。迁入 `exam` 的 PDF 文件仅作为历史交接资料保留，不在这里继续开发生成流程，也不将其限制计入本项目未完成任务。它们的历史检查记录不代表 `zhenti-pipeline-v2` 的现状。

## 导出方式

在项目根目录执行：

```bash
python3 tools/extract_bank.py --out .local/exports/zhenti-pipeline-v2
```

输出 `marx.json`、`physics.json` 和 `probability.json`，分别从 `web/exam/` 下相应页面的内嵌 JSON 提取。使用独立目录导出不会修改网页或 `bank-data/` 快照。需要刷新仓库快照时才显式执行不带 `--out` 的提取命令。

导出文件保持现有数据结构，包括 `meta`、`textbook`、`questions`，以及题目 ID、题型、来源、章节、选项、答案、解析和内嵌图片。消费者负责按自己的流程处理图片与排版；`exam` 导出器不承担 PDF 生产逻辑。

## 题目修正

正式网页题库中的确认修正随数据导出。个人 `data/` 中的 `corr` 覆盖层和历史 `bank-data-export/` 不会自动合并；其中包含用户人工勘误，版本差异不能直接视为错误。

合并前按题 ID 核对原值、修正值、字段和来源，保留经过确认的修正。导出只反映提取时的正式网页版本；对尚未并入正式题库的确认修正，需要先单独核对和维护，不能假定导出器已自动应用。

交接文件不包含个人作答记录、备注、AI 审核记录、访问口令或模型密钥。接收项目处理题库内容时仍需遵循原有来源与授权说明。

## 验证与历史资料

`exam` CI 检查网页与后端测试、首页内嵌页面和题量的一致性，以及三科 JSON 提取是否成功，不调用 PDF 生成或离线题册打包工具。

迁入文件的说明见 [历史离线包资料](offline-book.md) 和 [PDF 文件归属说明](pdf-roadmap.md)。跨项目实施进度应在 `zhenti-pipeline-v2` 核验。
